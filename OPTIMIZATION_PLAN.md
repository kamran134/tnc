## 📊 Анализ текущего состояния

### 🔴 Критические проблемы

#### 1. **Дублирование API вызовов**
**Проблема:** 29+ прямых вызовов `fetch()` в компонентах, хотя есть готовые API сервисы
- `src/app/dashboard/news/[id]/page.tsx` - 3 прямых fetch
- `src/app/dashboard/services/[id]/page.tsx` - 2 прямых fetch
- `src/app/dashboard/page-hero/page.tsx` - 2 прямых fetch
- `src/components/ui/PageHero.tsx` - прямой fetch
- `src/components/home/Hero.tsx` - прямой fetch
- И многие другие...

**Решение:** Использовать существующие API сервисы из `src/lib/api/`

#### 2. **Дублирование логики форм**
**Проблема:** Почти идентичный код в:
- `news/new/page.tsx` и `news/[id]/page.tsx`
- `careers/new/page.tsx` и потенциально в edit
- `services/new/page.tsx` и `services/[id]/page.tsx`
- Одинаковая логика: formData, handleSubmit, updateTranslation, ImageUpload

**Решение:** Создать универсальный хук `useAdminForm` и компоненты

#### 3. **Повторяющиеся data fetching паттерны**
**Проблема:** В каждой странице dashboard одинаковый код:
```typescript
const [data, setData] = useState([]);
const [loading, setLoading] = useState(true);
const [error, setError] = useState(null);
const loadData = async () => { ... }
useEffect(() => { loadData() }, []);
```

**Решение:** Создать универсальный хук `useDataFetching` или использовать React Query

---

### 🟡 Средние проблемы

#### 4. **Отсутствие мемоизации**
- Нет `React.memo` для дорогих компонентов
- Нет `useMemo` / `useCallback` где нужно
- Пример: `LanguageTabs` ре-рендерится при каждом изменении formData

#### 5. **Неоптимальная структура Context**
**LanguageContext:**
- Хранит слишком много логики
- Редиректы прямо в контексте (анти-паттерн)
- Нет мемоизации значений контекста

#### 6. **Избыточный console.log**
- В `client.ts` очень много логов в продакшене
- В `tokenManager` избыточное логирование

#### 7. **Отсутствие lazy loading**
- Все страницы dashboard загружаются сразу
- Компоненты не используют React.lazy

---

### 🟢 Мелкие проблемы

#### 8. **TypeScript `any` типы**
- В `news/[id]/page.tsx`: `const cleanedData: any`
- Потенциально в других местах

#### 9. **Дублирование loading состояний**
- LoadingSpinner дублируется в каждом компоненте
- Нет централизованного loading UI

#### 10. **Нет error boundaries**
- При ошибке падает весь UI
- Нет graceful degradation

## 📝 Вопросы для обсуждения

### 1. State Management
**Текущее состояние:** Context API + useState
**Проблемы:** 
- Много локального стейта
- Повторяющаяся логика загрузки данных
- Нет кэширования

**Варианты:**
- ✅ **React Query / TanStack Query** (рекомендую)
  - Автоматическое кэширование
  - Retry, refetch, prefetch из коробки
  - Оптимистичные обновления
  - Минимальные изменения кода
  
- ❌ **Redux Toolkit** (избыточно)
  - Слишком много boilerplate
  - Не нужен для этого проекта
  
- ❌ **Zustand** (не решает нашу проблему)
  - Хорош для глобального стейта
  - Но не решает проблему data fetching

**Рекомендация:** Установить React Query - это решит 80% проблем с минимальными изменениями
