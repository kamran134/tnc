# Исправление загрузки и отображения изображений

## Проблема
Бэкенд возвращал абсолютные URL для изображений (например, `http://localhost:8080/api/files/news_image/filename.jpg`), но Next.js блокировал загрузку внешних изображений, которые не были настроены в конфигурации.

## Решение

### 1. Создан API Proxy для изображений
**Файл:** `src/app/api/files/[...path]/route.ts`

Этот API route проксирует запросы к изображениям с бэкенда через Next.js:
- Принимает запросы вида `/api/files/news_image/filename.jpg`
- Перенаправляет их на бэкенд `http://localhost:8080/api/files/news_image/filename.jpg`
- Возвращает изображение с правильными заголовками кэширования
- Кэширует изображения на 1 час (3600 секунд)

### 2. Обновлен ImageUpload компонент
**Файл:** `src/components/ui/ImageUpload.tsx`

Добавлена конвертация URL из бэкенда:
```typescript
// Бэкенд возвращает: http://localhost:8080/api/files/news_image/filename.jpg
// Конвертируем в: /api/files/news_image/filename.jpg
let imageUrl = data.fileUrl;
if (imageUrl) {
  imageUrl = imageUrl.replace(/^https?:\/\/[^\/]+/, '');
}
```

### 3. Улучшена конфигурация Next.js
**Файл:** `next.config.js`

Добавлены дополнительные паттерны для разрешения внешних изображений:
- `localhost` и `127.0.0.1` для разработки
- `tnc.az` и `*.tnc.az` для продакшена
- Поддержка как HTTP (разработка), так и HTTPS (продакшен)

### 4. Обновлено использование изображений в новостях
**Файл:** `src/app/news/page.tsx`

Заменён обычный `<img>` тег на оптимизированный `<Image>` компонент от Next.js:
```tsx
<Image
  src={article.imageUrl}
  alt={article.title}
  fill
  className="object-cover"
  sizes="(max-width: 768px) 100vw, (max-width: 1200px) 50vw, 33vw"
/>
```

## Преимущества решения

1. **Безопасность** - все изображения проходят через Next.js API
2. **Оптимизация** - Next.js автоматически оптимизирует изображения
3. **Кэширование** - изображения кэшируются на клиенте и сервере
4. **Универсальность** - работает как в локальной разработке, так и в продакшене
5. **Совместимость** - не требует изменений в бэкенде

## Как это работает

1. Пользователь загружает файл через `ImageUpload` компонент
2. Файл отправляется на `/api/admin/files/upload`
3. Next.js API проксирует запрос на бэкенд
4. Бэкенд возвращает данные с полным URL: `http://localhost:8080/api/files/news_image/abc123.jpg`
5. Фронтенд конвертирует URL в относительный: `/api/files/news_image/abc123.jpg`
6. При отображении изображения Next.js запрашивает `/api/files/news_image/abc123.jpg`
7. Proxy API получает файл с бэкенда и возвращает клиенту

## Тестирование

Для проверки:
1. Запустите бэкенд на порту 8080
2. Запустите фронтенд `npm run dev`
3. Зайдите в дашборд и создайте новость с изображением
4. Проверьте, что изображение загружается и отображается корректно
5. Откройте Network вкладку в браузере и проверьте, что запросы идут на `/api/files/...`

## Переменные окружения

Убедитесь, что установлена переменная:
```env
BACKEND_URL=http://localhost:8080
```

Или в продакшене:
```env
BACKEND_URL=https://api.tnc.az
```
